# چطور یک AI Research Agent بسازیم که citation جعلی نسازد؟

اگر از Agent بخواهیم دربارهٔ یک موضوع مقاله بنویسد و در آخر فهرست منابع هم بسازد، روان‌بودن متن ممکن است citationهای ساختگی را پنهان کند. راه‌حل این نیست که از مدل بخواهیم «منبع خیالی نساز»؛ citation باید از رکورد قابل‌جست‌وجو بیاید، metadata آن اعتبارسنجی شود و ادعای متن جداگانه با منبع تطبیق داده شود.

در طراحی Academic Research Agent باید جست‌وجو، اعتبارسنجی citation، انتخاب روش، تحلیل و نگارش را به گام‌های جدا با معیار پذیرش روشن تقسیم کرد. نسخهٔ انگلیسی tutorial با [LangGraph](/writing/academic-research-agent/) هم در دسترس است.

## هر Citation را در دو مرحله بررسی کنید

اول باید پرسید: **آیا این اثر واقعاً وجود دارد؟** title، نویسنده‌ها، سال و DOI یا arXiv ID را از رجیستری یا صفحهٔ ناشر بگیرید. Crossref امکان resolve کردن DOI و جست‌وجوی metadata را می‌دهد؛ Semantic Scholar می‌تواند برای discovery و metadata کمک کند. این سرویس‌ها نتیجهٔ جست‌وجو می‌دهند، نه حکم علمی قطعی.

بعد بپرسید: **آیا این منبع واقعاً از ادعای موردنظر پشتیبانی می‌کند؟** DOI واقعی ممکن است به مقالهٔ دیگری برسد، یا مقاله وجود داشته باشد اما نتیجهٔ آن را متن وارونه خلاصه کند. بنابراین وجود citation و claim-to-source support دو gate جدا هستند. برای دومی باید متن یا بخش مربوطه را بازیابی و ادعا را با آن مقایسه کرد؛ DOI معتبر به‌تنهایی کافی نیست.

پژوهش Zhao و همکاران ۱۱۱ میلیون reference در ۲٫۵ میلیون مقاله از چند مخزن را بررسی کرد و برای سال ۲۰۲۵ عدد ۱۴۶٬۹۳۲ reference ناموجود را به‌صورت برآورد محافظه‌کارانه گزارش کرد. این عدد تخمینی از روش همان preprint است، نه شمارش دستی تک‌تک منابع؛ همچنین خودش ثابت نمی‌کند که هر reference ناموجود را LLM ساخته است.

## معماری پیشنهادی

سیستم را به یک گراف stateful با مرحله‌های مشخص تقسیم کنید. LangGraph یک گزینه برای مدل‌کردن state، nodeها و مسیرهای مشروط است، اما خود framework صحت علمی را تضمین نمی‌کند.

۱. **مرحلهٔ intake و پروتکل:** سؤال پژوهش را شفاف کنید، حوزه و نوع مطالعه را ثبت کنید و محدودیت‌های داده یا روش را مشخص کنید.
۲. **مرحلهٔ جست‌وجوی منابع:** queryهای جست‌وجو را بسازید، در چند منبع معتبر جست‌وجو کنید و برای هر رکورد، query و زمان بازیابی را ثبت کنید.
۳. **مرحلهٔ تطبیق citation:** title، نویسنده، سال و identifier را با رکورد DOI، arXiv یا صفحهٔ ناشر تطبیق دهید. موارد mismatch یا unresolved را به‌عنوان حل‌نشده نگه دارید؛ مدل نباید جای خالی را حدس بزند.
۴. **جدول شواهد:** برای هر claim، گزیدهٔ پشتیبان، منبع، بخش و نوع شواهد را نگه دارید. اگر نتیجهٔ پژوهش با ادعا تناقض دارد، تناقض را ثبت کنید.
۵. **بررسی novelty:** کارهای نزدیک و پیشین را جست‌وجو کنید و گزارش را به انسان بدهید. امتیاز novelty، اگر استفاده می‌شود، heuristic است و نمی‌تواند نوآوری را اثبات کند.
۶. **دروازهٔ روش‌شناسی:** مشخص کنید داده از کجا می‌آید، معیار چیست، baselineها کدام‌اند و چه محدودیتی باید گزارش شود.
۷. **پیش‌نویس و بررسی ارسال:** متن از evidence table ساخته شود، سپس منابع و declarationها بازبینی شوند. پیش از ارسال، پژوهشگر روش، نتیجه و کل manuscript را تأیید کند.

## اعتبارسنجی Citation با API

برای جست‌وجوی DOI و metadata می‌توان از Crossref REST API کمک گرفت؛ Semantic Scholar Academic Graph API هم paperها و authorها را پیدا می‌کند؛ PubMed برای زیست‌پزشکی و arXiv برای preprintها منابع اولیهٔ مناسبی‌اند. API جواب می‌دهد «چه رکوردی پیدا شد؟» اما معمولاً جواب نمی‌دهد «آیا این مقاله واقعاً این گزاره را می‌گوید؟»

برای هر citation، status روشن داشته باشید: verified metadata، metadata mismatch، unresolved یا source unavailable. فقط وقتی title، نویسنده و شناسه با رکورد منبع سازگارند آن را verified حساب کنید. اگر claim-to-source check خودکار است، نتیجه را confidence قطعی معرفی نکنید؛ برای ادعاهای اصلی review انسانی لازم است.

## چرا gateها باید ترکیبی باشند؟

مدل برای ساخت query، گروه‌بندی مقاله‌ها، خلاصه‌سازی و نوشتن draft انعطاف‌پذیر است. اما تطبیق DOI، وجود فیلد اجباری، توقف روی citation unresolved و gateهای تأیید می‌توانند تا حد زیادی قطعی باشند. در طرحی که در [مقالهٔ انگلیسی](/writing/academic-research-agent/) منتشر کردم، یک human approval gate کوچک را با LangGraph پیاده کردم؛ search adapterها و بررسی methodology همچنان به پیاده‌سازی جدا و منابع معتبر نیاز دارند.

برای کنترل عملی، human gate را در نقاطی بگذارید که تصمیم مسئولیت پژوهشی را عوض می‌کند: تأیید سؤال، انتخاب روش، تفسیر داده و نسخهٔ نهایی. Agent می‌تواند گزینه‌ها و evidence را آماده کند؛ مسئولیت علمی را نمی‌تواند از پژوهشگر بگیرد.

## خطاهای رایج

**منبع وجود ندارد.** citation را از پاسخ مدل کپی نکنید؛ از جست‌وجوی واقعی شروع کنید و status unresolved را نگه دارید.

**رکورد درست است، اما claim پشتیبانی نمی‌شود.** متن را با section و context کافی بخوانید و claim را جدا بررسی کنید.

**نسخه‌ها قاطی می‌شوند.** preprint، نسخهٔ کنفرانس و نسخهٔ نهایی می‌توانند سال یا عنوان متفاوت داشته باشند؛ هر نسخه را به identifier خودش وصل کنید.

**جست‌وجو کم‌پوشش است.** خروجی چند query را سند نهایی مرور ادبیات ندانید. دامنهٔ پایگاه‌ها، تاریخ جست‌وجو و محدودیت دسترسی باید در گزارش بماند.

**ارزیابی Agent به مدل سپرده می‌شود.** جملهٔ «نوآوری بالاست» از خود LLM evidence نیست. Gate باید queryها، مقاله‌های نزدیک و دلیل رد یا قبول هر مورد را نشان دهد.

## جمع‌بندی

یک Research Agent مفید پژوهشگر را از جست‌وجو، سازمان‌دهی رکورد و بررسی‌های تکراری آزاد می‌کند؛ اما نمی‌تواند به‌جای انسان اهمیت علمی، اعتبار روش و مسئولیت نتیجه را تأیید کند. هر citation را هم از نظر وجود و هم از نظر پشتیبانی ادعا بسنجید. اگر یک gate نتواند منبع و evidence را نشان دهد، خروجی آن مرحله هنوز آمادهٔ استفاده در مقاله نیست.
