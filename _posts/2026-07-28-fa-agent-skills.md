# مهارت Agent Skills چیست؟ چطور دانش کاری را قابل‌استفادهٔ دوباره کنیم؟

اگر هر بار که Agent یک کار تکراری انجام می‌دهد باید دوباره همان دستورالعمل‌ها را در prompt بنویسید، بخشی از دانش تیم هنوز به فرایند تبدیل نشده. Agent Skill یک بستهٔ قابل‌استفادهٔ دوباره از دستورالعمل، فایل‌های مرجع و در صورت نیاز script است که Agent می‌تواند هنگام مرتبط‌بودن بارگذاری کند.

برای طراحی Skill باید دو پرسش را جداگانه پاسخ داد: چه دستورالعملی برای انجام task لازم است و چطور می‌توان کیفیت آن را با feedback ارزیابی و بهتر کرد؟

## مهارت Agent فقط یک prompt طولانی نیست

طبق [مشخصات Agent Skills](https://agentskills.io/specification)، یک Skill حداقل پوشه‌ای با فایل `SKILL.md` است. فایل اصلی front matter و دستورالعمل دارد و می‌تواند به `scripts/`، `references/` یا `assets/` وصل شود. این ساختار، کار قابل‌تکرار را از جزئیات پروژه و ابزارها جدا می‌کند.

یک تشبیه ساده: اگر Agent به آشپزخانه دسترسی دارد، Tool همان وسیله‌ای است که می‌تواند با آن کاری انجام دهد؛ Skill دستور پخت و ترتیب استفاده از وسایل را توضیح می‌دهد. اما این تشبیه نباید مرز امنیتی را پنهان کند: داشتن Skill به‌تنهایی اختیار تازه‌ای به Agent نمی‌دهد. Toolها و مجوزها را runtime فراهم می‌کند.

یک Skill هم fine-tuning نیست. متنش وارد context می‌شود و رفتار مدل را از راه دستورالعمل هدایت می‌کند؛ وزن‌های مدل را تغییر نمی‌دهد. اگر script همراه Skill وجود دارد، اجرای آن وابسته به قابلیت و سیاست همان میزبان است.

## بارگذاری تدریجی چرا مهم است؟

اگر ده‌ها دستورالعمل را از ابتدا به مدل بدهیم، task اصلی و context مفید با اطلاعات نامرتبط رقابت می‌کنند. فرمت Skills برای بارگذاری تدریجی ساخته شده: ابتدا runtime نام و description مهارت‌ها را می‌شناسد؛ وقتی یکی از آن‌ها برای task مناسب شد، متن کامل `SKILL.md` را بار می‌کند؛ و فایل‌های جانبی فقط در صورت نیاز خوانده یا اجرا می‌شوند.

برای همین description باید بگوید Skill دقیقاً چه کاری انجام می‌دهد و چه زمانی باید فعال شود. توضیح مبهم ممکن است باعث شود Skill اشتباه انتخاب شود یا اصلاً پیدا نشود. درون فایل هم بهتر است مراحل، ورودی‌های لازم، خروجی موردانتظار و Gotchaهایی را بنویسید که از محیط واقعی می‌آیند، نه شعارهای کلی مثل «کیفیت را بالا ببر».

## چه چیزی را در SKILL.md بگذاریم؟

- **هدف و زمان استفاده:** این skill چه taskی را پوشش می‌دهد و چه taskهایی خارج از دامنه‌اند؟
- **ورودی و پیش‌نیاز:** Agent چه فایل، نسخه یا اطلاعاتی لازم دارد؟
- **مراحل اجرایی:** ترتیب کار چیست و در هر مرحله چه نتیجه‌ای انتظار می‌رود؟
- **روش بررسی:** چطور تشخیص بدهیم task واقعاً کامل شده؟
- **مرجع و script:** دستورالعمل طولانی یا ابزار کمکی را به فایل جدا منتقل کنید و فقط وقتی لازم است بخوانید.

یک Skill با دستور دائمی پروژه هم یکی نیست. `AGENTS.md` یا راهنمای مشابه معمولاً دربارهٔ conventionهای همیشگی repository است؛ Skill یک روند تخصصی و گاه‌به‌گاه را شرح می‌دهد؛ و Tool راه انجام عمل مشخص را فراهم می‌کند. مرز دقیق میان میزبان‌ها ممکن است متفاوت باشد، پس قابلیت واقعی محیطی را که در آن deploy می‌کنید بررسی کنید.

## پژوهش SkillOpt چه چیزی را اضافه می‌کند؟

در مقالهٔ [SkillOpt](https://arxiv.org/abs/2605.23904)، پژوهشگران فایل skill را state قابل‌بهینه‌سازی برای یک Agent ثابت در نظر می‌گیرند. مدل بهینه‌ساز trajectoryهای موفق و ناموفق را بررسی می‌کند و تغییرهای محدود به متن پیشنهاد می‌دهد؛ تغییر فقط زمانی پذیرفته می‌شود که روی validation score بهتر شود.

نویسندگان روی شش benchmark، هفت مدل و سه harness نتیجه گزارش می‌کنند. در تنظیم GPT-5.5، بهبود میانگین نسبت به حالت بدون Skill را ۲۳٫۵ **واحد درصد** در direct chat، ۲۴٫۸ واحد درصد در Codex loop و ۱۹٫۱ واحد درصد در Claude Code گزارش کرده‌اند. این اعداد نتیجهٔ همان آزمایش‌های مقاله‌اند، نه پیش‌بینی بهبود برای هر Skill یا هر مدل.

نکتهٔ عملی این است که تغییر متن هم باید eval داشته باشد. اگر grader ضعیف یا taskهای validation شبیه استفادهٔ واقعی نباشند، Skill می‌تواند برای نمره بهینه شود و در کار کاربران بدتر عمل کند. در زمان استفادهٔ نهایی ممکن است فراخوانی اضافه‌ای لازم نباشد، اما بهینه‌سازی خودش به rollout، مدل و verifier نیاز دارد و هزینه دارد.

## امنیت و سازگاری

هر Skill را مثل وابستگی نرم‌افزاری بررسی کنید. منبع و نسخه‌اش را بشناسید؛ scriptها و دستورالعمل‌هایش را بخوانید؛ سطح دسترسی لازم را بررسی کنید؛ و پیش از اجرا در محیط حساس، روی نمونهٔ کنترل‌شده تست کنید. یک Skill متنی هم می‌تواند prompt injection یا دستور خطرناک داشته باشد؛ صرفاً چون فایل Markdown است، بی‌خطر نمی‌شود.

فرمت باز به معنی رفتار یکسان در همهٔ Agentها نیست. یک میزبان ممکن است `SKILL.md` را بخواند اما scriptها را اجرا نکند؛ میزبان دیگر ممکن است metadata متفاوت بخواهد. سازگاری را با runtime واقعی و حداقل یک task نمونه بررسی کنید.

## جمع‌بندی

مهارت‌ها برای تبدیل یک روند تکراری به دستورالعملی قابل‌کشف و قابل‌بازبینی مفیدند. فایل کوچک و مشخص بسازید، description را دقیق بنویسید و رفتار را با task واقعی ارزیابی کنید. Skill ابزار جادویی یا مجوز اجرایی نیست؛ کیفیتش به شواهدی که برای ساخت و نگه‌داری‌اش دارید بستگی دارد.
